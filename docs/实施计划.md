# 实施计划：OpenTelemetry 智能体可观测性对照实验

## 1. 总体目标
在 `J:\workroom\otel-agent-lab` 目录下，基于 Conda 的 `pycharm` 环境（Python 3.11.5），搭建并验证两套 LangGraph 智能体可观测性方案（**方案 A：OpenTelemetry 自动插桩** vs **方案 B：OpenTelemetry 原生手动打点**），统一上报到本地启动的 **Arize Phoenix** 服务，并在前端 UI 中完成可视化对照与验收。

---

## 2. 阶段与任务拆解

### 阶段一：环境准备与增量依赖安装
* **目标**：确保运行环境完全绑定 Conda `pycharm` 环境，补齐 Phoenix 及自动插桩所需依赖。
* **具体任务**：
  1. 生成 `requirements.txt`：包含 `arize-phoenix`、`openinference-instrumentor-langchain` 等增量包。
  2. 使用指定解释器执行安装：
     ```powershell
     & "D:\win7app\anaconda3\envs\pycharm\python.exe" -m pip install -r requirements.txt
     ```
  3. 验证关键包可用性（导入测试）。

---

### 阶段二：观测平台部署脚本（run_phoenix.py）
* **目标**：提供独立的一键式启动脚本，拉起 Phoenix Web 服务及 OTLP 收集端口。
* **具体任务**：
  1. 编写 `run_phoenix.py`，配置监听端口为 `6006`。
  2. 暴露 OTLP Trace 接收端点：`http://localhost:6006/v1/traces`。
  3. 提供运行健康检查，确认打开浏览器即可访问 `http://localhost:6006`。

---

### 阶段三：方案 A 实现 —— 自动插桩智能体（agent_auto.py）
* **目标**：实现零侵入代码的 LangGraph ReAct 智能体。
* **具体任务**：
  1. 配置 OpenTelemetry 的 `TracerProvider` 与 `OTLPSpanExporter`（指向本地 Phoenix）。
  2. 激活自动插桩：调用 `LangChainInstrumentor().instrument(...)`。
  3. 构建 ReAct 智能体：
     * 定义数学计算工具：`calculate`
     * 定义代码搜索工具：`search_code_snippets`
     * 构建状态图（StateGraph），连接 `agent` 节点与 `tools` 节点。
  4. 注入标准测试 Prompt 运行。
  5. 验证是否自动捕获了节点跳转、LLM 输入输出及 Token 消耗。

---

### 阶段四：方案 B 实现 —— 手动打点智能体（agent_manual.py）
* **目标**：不使用自动插桩库，纯手动利用原生 `opentelemetry` SDK 构建完整的链路树与属性。
* **具体任务**：
  1. 初始化原生 `TracerProvider`，并注册 OTLP 导出器。
  2. 获取项目专属 Tracer：`tracer = trace.get_tracer("manual-agent")`。
  3. 显式埋点与上下文传递：
     * **Root Span (`agent_execution`)**：包裹整个 `app.invoke()` 调用。
     * **Node Span (`agent_reasoning`)**：在推理节点内手动创建，显式记录输入消息数、模型参数，并从 `response.response_metadata['token_usage']` 提取记录 Token 属性。
     * **Tool Span (`tool_execution`)**：在工具调用处显式捕获工具入参、执行耗时、返回值，并使用 `record_exception` 捕获异常。
  4. 注入相同测试 Prompt 运行。

---

### 阶段五：对照实验运行、验收与文档总结（README.md）
* **目标**：运行双方案，捕获 Phoenix 前端效果截图/对比数据，编写项目说明文档。
* **具体任务**：
  1. 分别运行 `agent_auto.py` 和 `agent_manual.py`。
  2. 在 `http://localhost:6006` 前端界面进行对比：
     * **Span 树形结构**：对比自动生成的粒度 vs 手动定义的粒度；
     * **元数据指标**：对比 Prompt 内容、Token 统计、属性键值格式；
     * **代码侵入性**：对比业务代码行数与耦合度。
  3. 编写 `README.md`，提供复现步骤与详细的优缺点对照结论。

## 4. 关键注意事项
1. **解释器强制约束**：开发与测试过程中，所有 PowerShell 命令必须使用 `& "D:\win7app\anaconda3\envs\pycharm\python.exe"`。
2. **大模型 API Key 兼容**：支持通过环境变量（`OPENAI_API_KEY`、`OPENAI_BASE_URL`）灵活配置或降级使用兼容的 OpenAI 接口（如 DeepSeek/通义千问等兼容服务）。
3. **Trace 刷新**：在脚本退出前，显式调用 `tracer_provider.shutdown()` 或 `force_flush()`，确保所有在内存队列中的 Span 批次 100% 成功发送到 Phoenix。
